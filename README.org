#+TITLE: clifff
#+STARTUP: content

=clifff= is a Common Lisp binding for the C interface of
[[https://github.com/dmtrKovalenko/fff][fff]]. It provides an in-process indexed search engine and an optional
supervised helper process for applications that need native crashes isolated
from their main Lisp image.

The current binding covers fuzzy file search, glob search, literal, regular
expression and fuzzy content search, and multi-pattern content search.

* Loading

#+BEGIN_SRC lisp
(asdf:load-system :clifff)

(defparameter *engine*
  (clifff:make-engine
   :library-path #P"/path/to/libfff_c.so"
   :base-path #P"/path/to/workspace/"
   :cache-directory #P"/path/to/private-cache/"))
#+END_SRC

The caller supplies the compiled fff C library, version 0.11.0 or newer.
=clifff= does not install a binary, modify =PATH=, or select a particular fff
revision. Content searches enforce their time budget even when nothing matches,
and the page's next file offset resumes at the first unsearched file.

Searches return readable property lists. Presentation helpers are provided for
compact terminal or model output.

#+BEGIN_SRC lisp
(clifff:render-file-result
 (clifff:engine-search-files *engine* "provider" :page-size 20))
#+END_SRC

Always close an engine when it is no longer needed:

#+BEGIN_SRC lisp
(clifff:engine-close *engine*)
#+END_SRC

* Supervised worker

=make-worker= accepts a command that loads =clifff= and calls =worker-main=.
The parent restarts a dead helper once and resets its private fff databases
before retrying. This process boundary protects the parent from accidental
native failures. It is not a security sandbox.

The request supplies its workspace, cache, fff library and diagnostic log
paths. Changing the log destination restarts the helper so distinct application
configurations do not share diagnostics accidentally.
